# Сборка ICU для Android

[English](../en/build-android.md) · **Русский** · [Документация](index.md) · [Windows](build-windows.md)

## Среда сборки

Инструкция использует существующий **Windows PowerShell**-скрипт [tools/BuildAndroid.ps1](../../tools/BuildAndroid.ps1). Исходники и `project.xml` общие с Windows. Сначала подготовьте локальные библиотеки по разделу [Зависимости](dependencies.md): одной глобальной установки Haxelib недостаточно, поскольку скрипт читает селекторы корневой `.haxelib/`.

| Инструмент или параметр | Текущая конфигурация |
| --- | --- |
| Haxe / Lime / OpenFL / hxvlc | 4.3.6 / 8.1.2 / 9.2.2 / 1.9.3 |
| JDK | 17; в зафиксированной локальной сборке — 17.0.20.1+1 |
| Компоненты Android SDK | Platform Tools, SDK Platform 30, Build Tools 30.0.3 |
| NDK | r21e, `21.4.7075529`, внутри каталога SDK `ndk/` |
| Android hxcpp | **4.3.175**, отдельно от активного Windows hxcpp 4.3.2 |
| Gradle / Android Gradle Plugin | 7.4.2 / 7.3.1 из генерируемого wrapper Lime 8.1.2 |
| Android minimum / target / compile API | 21 / 30 / 30 |
| Define нативной платформы | `HXCPP_ANDROID_PLATFORM=21` |

Скрипт ожидает Windows-файлы `java.exe`, `adb.exe` и `aapt.exe`. Установите компоненты SDK через SDK Manager Android Studio или консольный SDK Manager. Например, если `sdkmanager.bat` доступен в `PATH`, а `$icuSdk` содержит путь к вашему SDK:

```powershell
sdkmanager.bat --sdk_root="$icuSdk" "platform-tools" "platforms;android-30" "build-tools;30.0.3" "ndk;21.4.7075529"
sdkmanager.bat --sdk_root="$icuSdk" --licenses
```

Версии SDK/NDK взяты из текущего скрипта. Это конфигурация локальной сборки APK, а не проверенная конфигурация публикации в магазине по его текущим требованиям. Первая полная сборка требует сети для Gradle wrapper и Maven-зависимостей; отдельная глобальная установка Gradle не нужна.

## Отдельный Android hxcpp

Держите Android hxcpp в другом каталоге относительно Windows hxcpp. Передаваемая в `-HxcppPath` папка должна содержать `haxelib.json` с версией **4.3.175**, `run.n`, `hxcpp.n` и исходники runtime. Скрипт создаёт `.dev`-селектор на этот каталог; глобально переключать hxcpp не требуется.

**Пробел для установки с нуля:** исходная ревизия/архив локального hxcpp 4.3.175 не зафиксированы. Доступность именно этой версии как пакета Haxelib не подтверждена; проверенная [страница Haxelib](https://lib.haxe.org/p/hxcpp/) указывает 4.3.2. Не предполагайте, что `haxelib install hxcpp 4.3.175` сработает, и не подставляйте произвольную текущую Git-версию. Прежде чем гарантировать полностью воспроизводимую новую Android-среду, нужно установить точный снимок исходников/коммит.

Для подходящего снимка без скомпилированных инструментов [README исходного hxcpp](https://github.com/HaxeFoundation/hxcpp#building-the-tools) описывает `haxe compile.hxml` сначала в `tools/run`, затем в `tools/hxcpp`. В PowerShell, если `$icuHxcpp` указывает на этот отдельный снимок:

```powershell
Push-Location "$icuHxcpp/tools/run"
try { haxe compile.hxml } finally { Pop-Location }
Push-Location "$icuHxcpp/tools/hxcpp"
try { haxe compile.hxml } finally { Pop-Location }
```

Проверьте обе команды на ошибки перед продолжением. Они собирают инструменты, но не устанавливают недостающую исходную ревизию.

## Пути и действия сборки

Запускайте команды из корня репозитория. Задайте пути к **своим** установкам; диск и папки ниже служат только примером. Предполагается, что отдельный подходящий hxcpp из предыдущего раздела уже доступен.

```powershell
$icuSdk = 'D:\Android\Sdk'
$icuJdk = 'D:\Android\jdk-17'
$icuHxcpp = 'D:\Android\hxcpp-4.3.175'
$icuAndroid = @{
    SdkPath = $icuSdk
    JdkPath = $icuJdk
    HxcppPath = $icuHxcpp
}

.\tools\BuildAndroid.ps1 @icuAndroid -Action Check
.\tools\BuildAndroid.ps1 @icuAndroid -Action Prepare
.\tools\BuildAndroid.ps1 @icuAndroid -Action Typecheck -Architecture Universal
.\tools\BuildAndroid.ps1 @icuAndroid -Action Build -Architecture Universal
```

Передавайте параметры путей при каждом запуске или используйте карту `$icuAndroid` в той же сессии PowerShell. Стандартные расположения Java/hxcpp в скрипте — значения для удобства, а не обязательная структура каталогов. NDK ищется в `$icuSdk/ndk/21.4.7075529`; отдельного параметра `-NdkPath` нет.

| Действие | Что выполняет |
| --- | --- |
| `Check` | Проверяет файлы инструментов, версию hxcpp и библиотеки выбранных ABI; создаёт/обновляет профиль |
| `Prepare` | Также применяет исправления hxcpp; не запускает Lime update или сборку |
| `Update` | Запускает Lime update для цели; не компилирует C++ |
| `Typecheck` | Запускает Lime update, затем `haxe --no-output` для каждой выбранной ABI |
| `Build` | Применяет исправления hxcpp, выполняет нативную сборку и упаковку APK через Gradle |
| `Test` | Собирает, затем устанавливает и запускает на подключённом Android-устройстве через Lime |

`Check` не является полностью read-only: он записывает генерируемый профиль. Typecheck не создаёт новый APK и не проверяет runtime. По умолчанию все действия используют debug и **ARM64**, если параметры не задают другое.

```powershell
# По одной ARM ABI в APK.
.\tools\BuildAndroid.ps1 @icuAndroid -Action Build -Architecture ARMv7
.\tools\BuildAndroid.ps1 @icuAndroid -Action Build -Architecture ARM64

# Обе ARM ABI в одном APK.
.\tools\BuildAndroid.ps1 @icuAndroid -Action Build -Architecture Universal

# Release; подпись распространяемой версии настраивается отдельно.
.\tools\BuildAndroid.ps1 @icuAndroid -Action Build -Architecture Universal -Release

# Нужен подключённый телефон с разрешённой USB-отладкой.
.\tools\BuildAndroid.ps1 @icuAndroid -Action Test -Architecture ARMv7
```

Если локальная политика PowerShell блокирует скрипт, можно задать её для одного процесса; передайте те же реальные пути инструментов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\BuildAndroid.ps1 -Action Build -Architecture Universal -SdkPath "$icuSdk" -JdkPath "$icuJdk" -HxcppPath "$icuHxcpp"
```

Постоянная политика выполнения при этом не меняется.

## Архитектуры и расположение APK

| `-Architecture` | Нативные каталоги APK |
| --- | --- |
| `ARMv7` | `lib/armeabi-v7a/` |
| `ARM64` | `lib/arm64-v8a/` |
| `Universal` | Оба каталога выше; **без x86/x86_64** |

64-битному CPU с 32-битной Android нужен ARMv7. В Universal Android выбирает подходящую ABI. Список ABI подключённого устройства можно посмотреть так:

```powershell
& "$icuSdk/platform-tools/adb.exe" shell getprop ro.product.cpu.abilist
```

Корень debug-результата: `export/android-local/build/debug/android/`.

Debug APK: `export/android-local/build/debug/android/bin/app/build/outputs/apk/debug/InCrishUniverse-debug.apk`.

Корень release-результата: `export/android-local/build/release/android/`; внутри него смотрите `bin/app/build/outputs/apk/release/`. Итоговое имя release-файла зависит от подписи; одного `-Release` недостаточно для процедуры публикации/подписания.

Все архитектуры используют общий профиль и имя выходного файла: последняя сборка заменяет APK по этому пути. Сохраните нужные варианты отдельно перед следующей сборкой. Нативные кэши hxcpp разделены по ABI. Общие `assets/` упаковываются один раз, а встроенные в C++ ресурсы, например `art/`, входят в нативную библиотеку каждой ABI; Universal больше одноархитектурного APK.

## Изоляция профиля и исправления совместимости

Скрипт создаёт `export/android-local/project.xml`, подключающий актуальный корневой `project.xml`, и селекторы `.haxelib/` на общие библиотеки плюс отдельный Android hxcpp. Он не переключает корневой Windows hxcpp и не копирует все зависимости. Генерируемые файлы содержат машинные пути и не должны публиковаться; `export/` уже исключён из Git.

Для `Prepare`, `Build` и `Test` скрипт исправляет **отдельную установку Android hxcpp**:

- `Immix.cpp`: заменяет `std::atomic<T>::value_type` на `std::common_type<T>::type` и добавляет `<type_traits>` для libc++ из NDK r21; поведение CAS и порядок памяти сохраняются.
- `GcCommon.cpp`: добавляет `<cstdio>` для `std::sscanf`.

Оригиналы остаются рядом как `.icu-ndk21.original`. При неожиданном исходном шаблоне исправление останавливается; не обходите проверки версии/пути. Эти изменения остаются в установке hxcpp. Скрипт отклоняет путь, совпадающий с выбранным Windows hxcpp.

Переменные Java, SDK/NDK, Haxelib, `PATH`, числа потоков и Gradle действуют временно и восстанавливаются после команды. Постоянный `lime setup android` не нужен. Gradle запускается без daemon, с пустым `org.gradle.jvmargs` и предпочтением IPv4 для обхода ранее наблюдавшейся ошибки loopback. Лимит кучи задаётся непосредственно JVM через `GRADLE_OPTS`: `-Xms128m -Xmx4096m` по умолчанию. Параметр `-GradleHeapMB` меняет верхний предел в МиБ; он печатается перед запуском. Gradle ограничен двумя рабочими задачами, параллельная сборка проектов отключена. Параметры добавляются после унаследованных `GRADLE_OPTS`; постоянные настройки Java не меняются. `HXCPP_COMPILE_THREADS` по умолчанию равен 4, если не задан ранее.

## Особенности Android-порта

Записываемые файлы, `mods/`, `addons/` и относительные временные/редакторские пути используют приватное хранилище через `System.applicationStorageDirectory`. Встроенные ресурсы читаются по манифесту APK; видео получает байты, если реального файла нет. Android-логи идут в logcat. Доступ к общему хранилищу этим приватным каталогам не нужен. В игре нет Android-интерфейса импорта модов и сенсорного входа в переключатель модов из Main Menu.

Меню поддерживают прямые касания и drag-прокрутку; отпускание после drag не выбирает строку. Во Freeplay первое касание выбирает песню, второе запускает; у сложности и режима игры собственные сенсорные обработчики. Касания также реализованы для стартового видео/титла, панелей языка, Story, Credits, стандартной паузы и подтверждения темы. У Options своя кнопка назад, в других подходящих меню — шеврон с областью 80 × 80.

В игре используются четыре зоны на всю высоту из `assets/images/android/hitbox.png` и `hitbox.xml`, с мультитачем, удержаниями и переходом между зонами. Системный Back открывает паузу; отдельное последующее нажатие возвращает. Home и Recents сохраняют системное назначение; экранной кнопки паузы и отдельной сенсорной раскладки второго игрока нет.

В **Настройки → Сенсорное управление** непрозрачность задаёт яркость при нажатии; в покое зоны слабее. Ширина хитбоксов открывает редактор трёх разделителей с минимумом 10% на зону без наложений/зазоров. Сохранить применяет изменения, Назад восстанавливает исходные границы, Сброс раскладки возвращает равную ширину. Общий сброс сенсорных настроек также возвращает непрозрачность 0.4. Границы хранятся нормализованными в `touchLaneEdges`; неверные значения заменяются на `0.25/0.5/0.75`. Старые `touchLayout`, `touchSize`, `touchPositions` и `touchAtlasVersion` больше не загружаются. Ввод сбрасывается при потере фокуса и смене экрана; это само по себе не проверка полного цикла сворачивания/возврата.

Преобразование Android-шейдеров и ограничения описаны в [Изменениях движка](engine-features.md#изменения-только-для-android). Скриптовым интерфейсам может понадобиться собственная адаптация ввода.

## Возможные проблемы

- **Не найден обязательный файл:** проверьте явные параметры путей, SDK Platform 30, Build Tools 30.0.3 и точный подкаталог NDK. Скрипт также проверяет Lime, VLC и libc++ для каждой выбранной ABI.
- **Неверный hxcpp/версия или отклонён Windows-путь:** используйте отдельный 4.3.175 с обоими `.n`-инструментами. Исправления применяются в `Prepare`; `Check` и `Typecheck` их не вносят.
- **`Unable to establish loopback connection`:** скрипт уже задаёт описанный обход Gradle. Запускайте его вместо ручного повторения лишь части окружения.
- **`java.lang.OutOfMemoryError` в `:app:packageDebug`:** памяти не хватило Java-процессу упаковки на компьютере. Обновлённый скрипт по умолчанию ограничивает кучу 4096 МиБ и число рабочих задач двумя. Повторите прежний `Build`/`Test`; завершённая нативная компиляция обычно используется из кэша. Явное указание: `-GradleHeapMB 4096`. Не меняйте только `org.gradle.jvmargs` в генерируемом файле: в этом профиле упаковка идёт в JVM клиента, а свойство намеренно пустое. При повторной ошибке сохраните stacktrace и проверьте свободную память/файл подкачки, а также переопределения `_JAVA_OPTIONS` и `JAVA_TOOL_OPTIONS`.
- **Ошибка загрузки Gradle/Maven:** проверьте сеть и вывод разрешения зависимостей. Typecheck не проверяет полную упаковку через Gradle.
- **`INSTALL_FAILED_INSUFFICIENT_STORAGE`:** освободите место на устройстве и повторите установку. Размер APK не равен всему требуемому месту; прежнему Universal APK примерно 426 МиБ в наблюдавшемся сценарии обновления понадобилось больше 1.5 ГиБ свободного места. Это наблюдение, а не универсальный минимум. Не очищайте данные игры как обычный шаг сборки.
- **Несовместимая ABI:** сравните список ABI устройства с режимом APK. Разрядности CPU недостаточно; Universal здесь не содержит x86-библиотек эмуляторов.
- **Ошибка запуска/ресурсов или своего шейдера:** сохраните logcat и точные сведения о сборке/ABI. Прежние исправления путей не доказывают совместимость всех ресурсов, шейдеров и интерфейсов модов.

## Проверки без APK

Из корня проекта с подготовленной структурой форков:

```powershell
haxe -cp source -cp .haxelib/flixel/git -cp tools/tests --main TouchInputStateTest --interp
haxe -cp source -cp tools/tests --main TouchGestureStateTest --interp
haxe -cp source -cp tools/tests --main HitboxLayoutTest --interp
```

Существующие тесты проверяют события ввода при 30/60/120/240 FPS, быстрые касания, удержания, мультитач/сброс, drag и геометрию ширины, включая неверные сохранения и отмену. Они не проверяют доставку событий Android, координаты камер или производительность устройства.

При подготовке этой документации все три команды с интерпретатором прошли успешно.

## Границы проверки

В прежней разработке прошли полные ARM64 и Universal debug-сборки; последняя зафиксированная Universal-сборка включала обе ARM ABI и корректные подписи APK v1/v2. Ограниченные проверки на телефоне Samsung с 32-битной Android подтвердили стартовые видео, язык, титл, меню, повторный холодный запуск и загрузку игровой сцены с нотами/HScript. В прежних тестах также подтверждены tap/drag меню и эффекты шейдеров. Это исторические проверки, а не новый запуск с каждым текущим файлом исходников.

Более поздний Universal APK установлен обновлением с сохранением данных. Отдельная проверка на устройстве последних исправлений камер паузы/подтверждения темы и редактора ширины ещё предстоит. Полные треки, итоговое оформление HUD/тем/сцен, полный цикл загрузки/переключения модов, сворачивание/возврат и слабые устройства проверены не полностью. ARM64 runtime и совместимость эмуляторов не подтверждены. При подготовке этой документации новые APK, проверки подписи и сеансы на устройстве не запускались.
