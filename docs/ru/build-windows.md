# Сборка ICU для Windows

[English](../en/build-windows.md) · **Русский** · [Документация](index.md) · [Android](build-android.md)

## Инструменты и подготовка

Нужна Windows с **Haxe 4.3.6**, Haxelib, Neko и Git в `PATH`. Сначала выполните общую [подготовку зависимостей](dependencies.md); для Windows используется **hxcpp 4.3.2**.

Установите Visual Studio или Visual Studio Build Tools с компонентами **Desktop development with C++ / Разработка классических приложений на C++**, инструментами MSVC x64/x86 и Windows SDK. Точные версии MSVC/SDK для полной актуальной сборки ICU не установлены. Если автоматическое обнаружение не срабатывает, запустите команды из developer shell Visual Studio с настроенным окружением C++, затем перейдите в корень репозитория.

Все команды ниже выполняются из корня проекта. Не используйте для Windows окружение Haxelib из Android-профиля.

## Haxe typecheck

Сначала сгенерируйте файлы целевой платформы:

```powershell
haxelib run lime update windows -debug
haxe export/debug/windows/haxe/debug.hxml --no-output
```

`lime update` генерирует метаданные сборки и манифест ресурсов. `haxe --no-output` проверяет Haxe-код и макросы с этой конфигурацией. Он **не** компилирует C++, не линкует EXE и не проверяет игру. После изменения зависимостей, ресурсов или конфигурации пересоздайте целевые файлы: старый HXML не доказывает, что новый checkout собирается.

## Нативная сборка и запуск

```powershell
# Debug: Haxe, C++, линковка и подготовка ресурсов.
haxelib run lime build windows -debug

# Собрать и запустить debug.
haxelib run lime test windows -debug

# Release: без -debug.
haxelib run lime build windows
```

Ожидаемый результат по текущему `project.xml`:

| Конфигурация | Исполняемый файл | Каталог для распространения |
| --- | --- | --- |
| Debug | `export/debug/windows/bin/InCrishUniverse.exe` | `export/debug/windows/bin/` |
| Release | `export/release/windows/bin/InCrishUniverse.exe` | `export/release/windows/bin/` |

Сохраняйте рядом с EXE сгенерированные ресурсы и библиотеки runtime. Унаследованные команды разработки `cne test`/`cne build` привязывают ресурсы к исходникам; их результат не подходит для распространения отдельной независимой папкой.

## Известные проблемы

- **Нет `cl.exe` / ошибка компиляции PCH:** убедитесь, что C++ tools и SDK установлены и видны процессу сборки. Прежняя нативная попытка остановилась здесь после успешной генерации Haxe.
- **C1041 / общий `vc.pdb`:** `project.xml` задаёт `_CL_=/Z7` для `windows debug`, чтобы хранить отладочные сведения компилятора в объектных файлах. Поэтому возможно предупреждение D9025 о переопределении `/Zi`. Настройка заменяет ранее заданный `_CL_` в дочерних процессах сборки и не действует для release. Полная успешная debug-сборка после этого обхода не подтверждена.
- **WMIC недоступен:** `SystemInfo` и `MemoryUtil` всё ещё используют WMIC для сведений о CPU/RAM. Эта зависимость не удалена; typecheck не проверяет её наличие в runtime.
- **Ошибки библиотек или макросов:** проверьте [форки, версии и ревизии](dependencies.md). При отсутствии сгенерированного `assets.json` повторите `lime update`, а не копируйте генерируемые файлы другого разработчика.

## Границы проверки

В прежних проверках ICU успешно проходил Windows debug Haxe typecheck, в том числе после Android-изменений. Полный новый Windows debug/release EXE и визуальная/игровая проверка Windows не подтверждены. Ранее пользователь сообщал об успешном release, но это не проверка всех последующих изменений исходников. Команды выше соответствуют текущему проекту и инструментам; свежую C++-сборку Windows ещё нужно подтвердить.
